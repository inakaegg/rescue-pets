# 002 — Cloudflareを使わない

前段のCDN・WAFとしてCloudflareを置かず、AWS WAFも使わない。外部サービスはAWSだけに限る。

## 理由

- 外部アカウントと秘密情報の管理先が増える。Cloudflareを前段に置いても、オリジン（API Gateway）のURLが知られると前段を素通りして直接アクセスできてしまう。これを防ぐ定番は「Cloudflareが付ける秘密ヘッダーをオリジン側で検証する」方式だが、その秘密値をCloudflareとAWSの両側で管理・更新し続ける必要がある。
- AWS WAFはHTTP APIに直接付けられない。付けられる構成に変えても月 $5 程度の固定費が出る。無料枠を軸にするPoCには合わない。
- 防ぎたいのは課金の暴走であり、それはAPI Gatewayのスロットリングと日次カウンタで足りる（[cost.md](../cost.md)）。

## トレードオフ

- 大規模なDDoSをエッジで吸収する層がない。PoCの公開範囲では許容する。
- 将来実データ運用へ進み、攻撃面が変わったら判断を見直す。
