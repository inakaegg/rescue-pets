# 検索の仕組み

「小型で子どもと暮らせる犬」のような自由文から、条件に合う掲載を確からしい順に返す仕組みを説明します。

## 4段の流れ

Embeddingとベクトル類似度検索は使いません。初版の50件でも、実データを想定した数万件でも、次の4段で足ります。

1. LLMが自由文を構造化条件（種別・都道府県・サイズ・年齢区分・相性・キーワード）へ変換する。
2. 保存先から全件を読み、構造化条件で絞り込む。該当項目が `unknown` の掲載は除外しない。
3. キーワードと紹介文の文字3-gramの重なりで粗い順位を付け、上位20件程度に絞る。
4. LLMが上位候補を読み、確からしい順に並べ替えて理由を1行添える。

初版は50件なので、3の絞り込みが効く場面は多くありません。件数が増えてもLLMへ渡す量を一定に保つための段です。

## 団体の登録でも同じ構造化を使う

ログインした団体が写真と自由文メモを送ると、AIが「種別・推定年齢・性格・譲渡条件」などを構造化して掲載します。構造化は登録操作の中で同期に行います。LLMは数秒で返るため、初版では待ち時間を許容します。件数が増えて待たせるようになったら、非同期化（SQS）を検討します（[ROADMAP](ROADMAP.md) の「後回しにする機能」）。

## 使うモデルと呼び出し方

AI（LLM）にはAmazon Bedrock上のGPT-5.6 Luna（以下Luna）を使います。

- Lunaは、リージョンを1つに固定した呼び出し（リージョン内推論）に対応していない。そのため、クロスリージョン推論プロファイル（`global.openai.gpt-5.6-luna`）を名指しして呼ぶ。呼び出し自体はLambdaと同じ東京リージョンの `bedrock-runtime` へ送り、実際の推論先はAWSが選ぶ。
- 権限はLambdaのIAMロールに、この推論プロファイルへの `bedrock:InvokeModel` を付ける。許可対象のARNの正確な形は、sandbox構築時に実物で確認する。
- Structured outputsは非対応なので、JSONはプロンプトで指示してスキーマ検証する。

呼び出し回数と費用の上限は [cost.md](cost.md) を参照してください。

## テストの方針

- LLMの代替（語彙ルールのスタブなど）は作らない。
- 自動テストはBedrockの実応答を一度記録して再生し、絞り込み・並べ替え・スキーマ検証など周辺のロジックだけを固定する。ネットワークやAPIキーなしで実行できる。
- LLM出力の品質は、テストの成功ではなく、代表入力を本物に流した結果で確認する。
