# ROADMAP — 実装の順序と進み具合

実装状況を書く場所はこのファイルだけです。他の文書は設計と仕様を書き、進み具合はこことgit履歴で追います。

## いまの状態

雛形の段階です。フロントエンドとAPIの骨組みだけがあり、機能の実装はこれからです。見本掲載の素材（写真と紹介文）は別リポジトリ `pets-image` で50件をSDXL（1024px）で作ってあります。写真50枚は `public/pets/` へ取り込み済みです。紹介文の取り込みは、構造化（`pets structure`）と投入（`pets seed`）を実装するときに行います。自動テストは、いまのところ掲載写真の検査だけがあります。

## 実装の順序

各機能は、まず手元から実行できる形（CLIかローカルのAPI）で作り、Web UIをその上へ重ねます。検索はCLIを作らず、ローカルで起動したAPIへcurlを投げて確かめます。同じ処理を二重に持たないためです。

1. **見本掲載** — 未着手。`pets structure` が紹介文をLLMで構造化して `data/listings.json` へ固定し、`pets seed` がそれを投入する（どちらも未実装）
2. **バックエンドをsandboxで** — 未着手。CDKでDynamoDB・HTTP API・Lambda（Hono）・Bedrock権限と費用の上限（[cost.md](cost.md)）を定義し、`npx ampx sandbox` で展開する。`pets seed` で投入し、`POST /search` が期待どおりの候補を返す
3. **利用者向けWeb UI** — 未着手。検索・詳細・一覧。手元の `npm run dev` がsandboxのAPIを使う
4. **団体向け** — 未着手。Cognitoログイン、登録（メモをBedrockで構造化）・編集・削除、掲載管理画面
5. **公開** — 未着手。gitリモートへpushし、Amplifyアプリにブランチを接続してHostingへ
6. **後回しにする機能**（下の一覧）

機能の自動テストは順序1で導入します。いま動くのは掲載写真の検査（`npm run test:pet-assets`）だけです。

## 後回しにする機能

初版に含めません。設計上の置き場所だけ決めてあります。

- **LINE新着通知** — 保存した検索条件に合う子が載ったときにLINEで知らせる。追加時はLINE Messaging APIのWebhookをLambdaで受け、保存条件はDynamoDBの同じテーブルへ置く
- **埋め込みウィジェット** — 団体の既存サイトへ1行のタグで掲載一覧を埋め込む
- **写真のアップロード** — 初版は写真をURLで指定する。S3への直接アップロードは後から足す
- **構造化の非同期化（SQS）** — 登録件数が増えて同期処理が待たせるようになったらSQSを挟む
- **一覧ページの静的生成** — 実データ運用で検索エンジン流入を狙う段階になったら行う
- **クローラ（収集）** — 架空の公示ページを収集してAIで構造化する経路。初版のデータはseedで直接作るため不要
